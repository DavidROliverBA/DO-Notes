# F31 — Relationship builder

Done 2026-11-01, all four steps (see the CHANGELOG); David checked it with VoiceOver on the iPhone that day. The design as it stood in the backlog.

**Size** M–L, in four steps · **Evidence** asked for 2026-10-31: changing a link's direction
(was F29, after boards, F11), then "a building function to support the relationships … designed
and thinking about accessible" once F9 gave notes ids and typed links; AI-XF typed links (§6)
and `vocab/rels.json`; WCAG 2.2 (2.5.7 dragging movements, 2.4.11 focus not obscured, 2.5.8
target size, 4.1.3 status messages)

Relationships exist today in pieces: relation properties a type defines (`attendees`), **Add
relationship…** in the properties panel with AI-XF's core kinds (F27, `RELS` and `relNamed` in
`src/types.ts`), and board arrows that can become a relation (F11). There's no one place to see,
make and change a note's relationships, turning one round means deleting it and writing it
again, a board arrow can only be drawn by dragging, and nothing puts relationships into words a
screen reader can follow.

Wanted: **one relationship builder, used everywhere**, that reads as a sentence.

**Stays as decided (2026-10-12):** a relationship is a property in the note it starts from
(`comes-before: [[Loft]]` in Roof), and becomes a typed link (`links: [{rel, to}]`) only in an
AI-XF bundle (F9). Type relations (`attendees`, `owner`) and free relationships (*comes
before*) share the one builder and the one list; a type's own relations are offered first.

1. **Arrows turn round, and are made without dragging (S), built 2026-10-31:** **Reverse** on a selected arrow
   swaps its ends, sides and arrowheads, one Undo. **Connect to…** on a selected card picks the
   other card from a list, so an arrow never needs a drag (2.5.7). An **Arrows on this board**
   list gives every arrow as a sentence (*Roof → comes before → Loft*), each one selectable,
   as the board's text alternative.
2. **The kinds of relationship (S–M), built 2026-10-31:** one list per collection, kept as a Markdown note
   (`Relationships`, beside `Types/`, so it travels with the files): AI-XF's core kinds, the
   relations the types define, and kinds a person adds. Each kind has a name, a name for the
   other direction (*comes before* / *comes after*) and a one-line meaning; symmetric kinds
   (*relates to*) have one name. It is what export writes as `vocab/rels.json`, and import
   adds a bundle's kinds to it.
3. **The builder (M), built 2026-10-31:** three labelled controls that read as one sentence, **[Roof] [comes
   before ▾] [Loft ▾]**, with the whole sentence announced as it changes (a polite live region,
   4.1.3) and **⇄ Swap** to make it *Loft comes after Roof*. Choosing the kind and the note are
   both type-to-filter lists that work by keyboard alone; a new kind can be added from it. It
   opens from the note's ⋯ menu, ⌘K, `/` in a note, the side panel, and a board arrow (where
   it replaces **Make the arrow a relation…**). It replaces today's **Add relationship…**.
4. **Every relationship in one place, and turned round (S–M), built 2026-11-01:** a **Relationships** section in
   the side panel, grouped by kind, showing both directions with their own names (*Loft · comes
   after · Roof* on Loft). Each row can be opened, swapped, changed or removed by keyboard, with
   Undo. **Reverse** on a relation takes it out of this note and writes it into the other note
   under the other direction's name, in one step that Undo takes back.

**Accessible from the start**, not checked at the end: every step is done by keyboard and with
VoiceOver on the Mac and the iPhone (the check still open in N12); meaning never rests on
colour, position or an arrowhead alone, always on the sentence; every control has a name;
focus is never hidden under the toolbar or a popover (2.4.11); targets are at least 24 px
(2.5.8); making, swapping and removing a relationship is announced.

**Done when** a relationship can be made, read, swapped, reversed and removed by keyboard
alone and with VoiceOver on the iPhone; a board arrow can be drawn and reversed without
dragging; the other note shows each relationship under the right name; a collection's own
kinds and their other-direction names export to `vocab/rels.json` and come back on import; and
a reversed relation exports as a typed link with the right direction.
