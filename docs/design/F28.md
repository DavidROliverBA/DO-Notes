# F28 — Writing blocks from Confluence

**Size** M overall, each part S · **Evidence** the Confluence gap analysis (2026-10-26): of
Confluence's built-in features, these are the writing ones Commonplace lacks that turn up in
nearly every real space, so an import would look broken without them.

1. **Expand:** `> [!note]-` folds closed and `> [!note]+` open, in Live Preview and reading view
   (the fold marker is read and ignored today, `web/lib/render.ts`).
2. **Status:** a coloured label inline, written so other editors show it as text.
3. **Table of contents:** a block that lists the note's headings and follows them.
4. **Date:** `//` (and the `/` menu) picks a date and writes it as ISO.
5. **Emoji:** `:name` suggests emoji as you type; a note can have an emoji icon (`icon:`
   property) shown with its title in the tree, tabs and links.
6. **Cover image and page width:** `cover:` and `width: wide` properties.
7. **Link cards:** a URL on a line of its own shows as a card (title, site, picture), from the
   weblink fetcher (`src/weblinks.ts`).

**Done:** 1–4 in v0.0.63, 5–7 in v0.0.64 (see the CHANGELOG).

How each is written, so it stays plain Markdown: `> [!note]-` / `+`; `:status[Label]{.colour}`
(the generic directive syntax); `[TOC]` (as Typora, GitLab and Python-Markdown write it); dates
as `YYYY-MM-DD`; emoji as the characters themselves; `icon:`, `cover:` and `width:` properties
(a note in `Types/` keeps `icon` for its type's icon); a link card is just the address on its
own line. Published sites get the fold, status and contents; link cards stay plain links there,
since a site is a snapshot and its pages fetch nothing.

Left out on purpose (see Decided against in the backlog): Confluence's page tree (F27's
relationships instead), layouts and columns, and tables with merged cells.

**Done when** each works in Live Preview and reading view, on the iPhone, in both themes, stays
plain Markdown other editors read sensibly, and has help and a browser test.
