# F35 — Reminders for dated tasks (done 2026-11-01)

**Why:** the [gap analysis](../GAP-ANALYSIS.md) found it the biggest everyday gap: due dates showed
only on the Tasks page, and nothing told you on the day.

**Decided with David (2026-11-01):**
- **Delivery: the apps schedule them.** The iPhone and Mac apps fetch `GET /api/me/reminders`
  with the web view's sign-in and schedule local notifications (`ios/Shared/Reminders.swift`).
  No push service, so no Apple push key and no Web Push; alerts arrive offline. The browser
  doesn't alert.
- **Whose tasks:** an open task with a date (📅) in a note you wrote or last edited, or one that
  names you (`@First`, `@Full Name`, `[[Full Name]]`). A shared collection's other tasks remind
  their own people.

**How it works:**
- `src/reminders.ts` lists tasks due from yesterday to 14 days ahead (at most 200), each with a
  stable key (vault, note and the task's words) and a local time: the task's `⏰ HH:MM` (or
  `⏰ date HH:MM`), else the person's reminder time (Settings → Account, default 09:00), stored
  in `users.reminders_on` and `users.reminder_time`.
- The apps refresh the list whenever they check the sharing token (opening, coming back, page
  loads; at most every 30 s), and the iPhone also in a background refresh (`BGAppRefreshTask`).
  Each refresh replaces the scheduled alerts (at most 56: iOS keeps 64), keeping snoozes.
  Signed out → all removed.
- An alert's **Done** ticks the task through the Tasks page's own route (`PATCH …/tasks`, with
  the cookie and the server's Origin); **Remind me in an hour** schedules it again; a tap opens
  `commonplace://open/v/<vault>/n/<note>`.

**Later, if wanted:** alerts in the browser (Web Push), repeating tasks (🔁), and a badge with
the count due today.
