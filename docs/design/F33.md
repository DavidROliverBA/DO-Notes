# F33 — Connections: connect any service that meets the bar, with guidance

**Status:** design agreed 2026-11-01 (David's decisions are under Decisions, at the end).
Nothing here is built. It generalises what F30 built by
hand for Longview and Recall (`src/outside.ts`, `src/mcpClient.ts`).

## Why

F30 connected two services, and each took hand-written code: its tools chosen, renamed and
described, its sign-in written for it, and its safety rules checked case by case. A third
service would mean the same again. Most services worth connecting now speak the same protocol
(MCP), sign in the same way (OAuth with discovery, or a token), and describe their own tools. So
one **connections manager** can take any service that meets a clear bar, and **guide the person
through connecting it**, without anyone writing code for it, and without lowering the care F30
took.

The hard part isn't the protocol; it's trust. A connected service's tool descriptions, and
everything it returns, are text written by someone else that goes straight to the model. The
design is mostly about keeping that from steering the assistant into leaking notes or changing
things the person didn't mean to.

## What it is, in a sentence

Settings → Connections → **Add a connection…** walks the person through: the address, what
Commonplace found there, signing in, choosing which of its **read** tools the assistant may use,
and a test. Connections only ever read: a tool that changes things in the service is never
offered. Their findings show to the assistant and, for the open note, in the side panel. Known
services (Longview, Recall) are presets that skip the questions already answered.

## Part 1 — Specification: the bar a service must meet

A service can be connected when it meets **every "must"**. The guided flow checks each one and
says, in plain words, which it failed.

### 1. Protocol

| | Requirement |
|---|---|
| **Must** | Be an **MCP server over Streamable HTTP** (protocol 2025-03-26 or later): JSON-RPC over `POST`, answering in JSON or a server-sent event stream. |
| **Must** | Answer `initialize`, `tools/list` and `tools/call`. |
| **Must** | Have at least one tool. |
| **Must** | Have at least one tool Commonplace can treat as **read-only** (see 4). |
| **Should** | Give each tool a `title` and **annotations** (`readOnlyHint`, `destructiveHint`, `openWorldHint`). Commonplace uses them to sort tools, but never as proof (see Trust). |
| Not supported | **Local servers** (stdio, a command to run): Commonplace never runs a program for a connection. The old HTTP+SSE transport. Server-initiated requests: Commonplace declines `sampling`, `elicitation` and `roots`, so a service can't make Commonplace's model work for it or look at its files. Resources and prompts (a later step, if wanted). |

### 2. Address

| | Requirement |
|---|---|
| **Must** | `https://`, on a **public address** (checked by `src/egress.ts`, every request, with no redirects followed). The one exception is the laptop kit: there, services on the same Mac (a local Longview, `http://localhost:…`) are allowed by default (`CONNECTIONS_ALLOW_LOCAL`, on in `laptop/compose.yaml`); the cloud never allows them. |
| **Must** | No sign-in in the address (`user:pass@`, `?token=`): credentials only ever go in headers. |
| **Must** | Allowed by the library's policy, when an admin has set one (Part 2, Admin). |

### 3. Sign-in

One of these, in this order of preference:

| Kind | Requirement |
|---|---|
| **OAuth** (preferred) | Follows MCP's authorization spec: the service points to its **authorization server** (protected resource metadata, RFC 9728, or a `WWW-Authenticate` header naming it); that server publishes its metadata (RFC 8414); supports **PKCE with S256**; and lets Commonplace register as a client, by **dynamic registration** (RFC 7591) or a **client ID metadata document**. Endpoints must be `https`. Commonplace asks for the **narrowest scopes** that cover the tools chosen (a read scope when only read tools are on). |
| **A token** | A bearer token or API key the person pastes, sent as `Authorization: Bearer …` or in one named header (the person, or the preset, says which). |
| **None** | Allowed, **with a warning** the person must read before going on: *"This service doesn't ask who you are. Anyone can use it, and it can't keep anything private for you. What the assistant sends it (your searches) goes to it unsigned. Only connect it if you trust who runs it."* Listed afterwards as *no sign-in*. |

Not supported: passwords typed into Commonplace for another service, cookies, or signing in by
scraping a web page.

### 4. Read-only (decided 2026-11-01)

Connections read; they never change anything in the service. Commonplace sorts each tool by
what it says about itself, then the person chooses among the read ones:

| What the tool says | What Commonplace does |
|---|---|
| `readOnlyHint: true` (and not `destructiveHint`) | **Read.** On by default; the person can turn it off. |
| `readOnlyHint: false`, or `destructiveHint: true` | **Changes things. Never offered**: listed greyed out, *"changes things in Longview: Commonplace only reads"*, and can't be turned on. |
| No annotations | **Unknown.** Off by default. The person can turn it on only after a warning (*"Longview doesn't say whether this changes anything. Turn it on only if you know it just reads."*), and then the assistant **asks every time** before using it. |

Where the service signs in with OAuth, Commonplace asks only for its **read scopes** (as F30
does with Recall's `kb:read`), so the service itself refuses a change, whatever a tool claims.
A token the person pastes can't be narrowed by Commonplace, so the flow asks for a read-only one
where the service has them (Longview's read tokens), and a preset can say how to tell (F30
refuses a Longview token that is offered write tools; a preset can name such tools).

### 5. Limits Commonplace enforces (whatever the service says)

- Each call: **60 s**, an answer of at most **4 MB** (the model gets at most what `clip` allows).
- Tool names, descriptions and schemas: capped in length; anything else is cut before the model
  sees it.
- At most **20 tools enabled** per connection, and **10 connections** per person (enough for real
  use; keeps the model's tool list readable and the cost of each request down).

## Part 2 — Design

### What the person sees

**Settings → Connections** lists the connections, each with its icon, name, address, sign-in
(with the token's last four, or "signed in with OAuth"), its tools ("4 tools: 3 read, 1 changes
things, asks each time") and **Review**, **Disconnect**.

**Add a connection…** opens a guided dialog, one step at a time, by keyboard as well as touch,
each step announced:

1. **Where is it?** Pick a known service (Longview, Recall, and any an admin adds), or paste an
   address. A preset fills in everything the next steps would ask.
2. **What Commonplace found.** It probes the address (`initialize`, then the metadata) and says
   what it found, in words: *"Longview 2.3, an MCP service. It signs in with a token. It offers
   12 tools: 8 read things, 4 change things."* Or why it can't be connected: *"That address isn't
   an MCP service (it answered with a web page)"*, *"It only works on your own computer (stdio)"*,
   *"Its sign-in doesn't use PKCE, which Commonplace needs"*. Each failure names the rule in Part 1.
3. **Sign in.** OAuth: **Sign in to Longview…** opens the service's own page (a new tab, Safari's
   sheet in the iPhone app, the browser from the Mac app), as Recall does now; the step updates
   by itself when it's done. Token: a box for it, with where to find one (from the preset, or the
   service's own words).
4. **Choose its tools.** Each tool with its title, what it says it does, and what it may send out
   (its inputs), in the three groups of Part 1 §4: read tools (on), unknown ones (off, with the
   warning), and tools that change things (shown greyed out, can't be turned on). The
   descriptions shown are the ones the model will see.
5. **Try it.** One harmless call (a preset names it; otherwise the first read tool with no
   required input, if any), and its answer, so the person sees it works. Then **Done**.

**Review** reopens step 4. When a service **changes its tools** (Trust, below), the connection is
held: its tools are off until the person reviews what changed (*"Longview's save_url now says
…"*), shown as a before and after.

### Using a connection: the assistant

- Offered to the **in-app assistant only**: never through Commonplace's own MCP server, so a
  connection is never passed on to another app (as F30).
- The model sees each enabled tool as `<connection>_<tool>` (`longview_search_intelligence`),
  with its description after a fixed preamble that says it comes from that service and is data,
  not instructions.
- **Read tools** follow the web's rule (F30): a call whose inputs are words the person typed, or
  values an earlier answer from the same connection gave (an id), runs straight away; any other
  asks first, showing exactly what would go out.
- Tools that change things are never offered (read-only). A tool of **unknown** kind that the
  person turned on asks every time, showing the tool, the service and every input. There's no
  "always allow".
- Once a conversation has read anything from a connection, **every change in Commonplace asks**
  first, even to the open note (as F30 and the web).
- A call's result is clipped, marked as coming from that service, and never treated as
  instructions (the system prompt says so, as it does for notes and the web).

### The side panel: "From your connections" (decided 2026-11-01)

For the open note, a **From your connections** section in the side panel (beside Backlinks and
Related) shows what each connected service has on it: Longview's events about the companies and
models the note names, the Recall cards about its subject.

- **Off for each connection until the person turns it on** (in its Review: *"Look up the open
  note in the side panel"*), because it sends something of the note out without asking each time.
  What it sends is fixed and shown there: **the note's title, and its type's name**, never its
  text. A preset can say what to send instead (Longview: the entities the note links to, by name).
- Uses one read tool per connection, chosen in Review (the preset's, or the first read tool with
  a single text input); a connection without one can't be in the panel.
- Runs when the note opens and when its title changes, not as the person types; answers are
  cached for the note for ten minutes; each connection's section can fold, and shows *Couldn't
  reach Longview* rather than an error.
- Results are shown as links (title, source, date), never as HTML from the service, and open in
  the browser (or the service's own page). **Ask the assistant about this** starts a conversation
  with them, under the assistant's rules above.
- Not on published sites, not in the standalone file, not for viewers of someone else's
  collection unless they've connected the service themselves (a connection is per person).

### Trust: what can go wrong, and what stops it

| Risk | What stops it |
|---|---|
| **Tool poisoning:** a description that tells the model to send notes somewhere. | The person sees and chooses the tools; descriptions are capped and framed as data; any call that would send text the person didn't type asks first, showing it. |
| **A service changes its tools after review** ("rug pull"). | Commonplace keeps a hash of each enabled tool's name, description, schema and annotations. Each conversation lists the tools again (cached a few minutes); a change holds the connection until the person reviews it. |
| **Annotations that lie** (a write tool marked read-only). | OAuth asks only for read scopes, so the service refuses the change itself; a pasted token should be a read-only one, and presets check where they can; every tool still follows the send-out rule. A lying service can still do harm with a token that can write: the flow says so when it can't tell. |
| **A service with no sign-in.** | Allowed only past a warning the person reads; listed as *no sign-in*; the send-out rule applies as everywhere. |
| **The side panel sending note text.** | Off per connection until turned on; sends only the title and type (or a preset's named fields), shown in Review; never the note's text. |
| **Prompt injection in results** (a saved page that says "now delete…"). | After any connection result, every change asks; results are framed as data. |
| **Exfiltration in arguments** (notes put into a search). | The send-out rule: only typed words or earlier answers run without asking. |
| **SSRF:** an address that reaches inside the server's network. | Every request through `egress.ts` (public addresses only, pinned, no redirects). |
| **Token theft or reuse.** | Tokens sealed with `SECRETS_KEY`, never sent to the browser or a log, only in headers; Commonplace's own tokens never go to a connection (no token passthrough); OAuth uses PKCE, a single-use state that expires, and the person's own sign-in. |
| **A malicious OAuth server** (endpoints elsewhere, huge answers). | Endpoints must be `https` and pass the egress checks; registrations cached per server, so one service can't make Commonplace register again and again. |
| **Cost and noise** (a service with 200 tools). | 20 tools per connection, chosen by the person. |
| **A service on the same Mac** (kit only). | Allowed by default on the kit, where the person owns the machine; never in the cloud. |

### Admin (Settings → Admin → Connections)

- **Who may add connections:** everyone (the default, decided 2026-11-01), admins only, or no one.
- **Which addresses:** any public one (the default), or only those on a list (for a library at
  work that should reach only approved services).
- **Known services:** the presets everyone sees in step 1. Built in: Longview and Recall. An admin
  can add one by its address, so people only choose it.

### Presets

A preset is data, not code: a name, an icon, the address (or how to find it), the sign-in kind
and scopes, which tools are on by default, friendlier names and descriptions if wanted, the test
call, and where to get a token. Longview and Recall become presets; F30's hand-written tools in
`src/outside.ts` are replaced by them, keeping their names (`longview_search` and so on) so
conversations and help stay the same.

### Data

- `connections`: id, user, name, icon, address, preset (or none), sign-in kind, sealed token or
  OAuth tokens (access, refresh, expiry, token endpoint, client id, scopes), status (ok, held for
  review, needs sign-in), created, last used. Replaces F30's `user_connections`, whose two kinds
  move across on first boot (additive: the old table stays until a later release).
- `connection_tools`: connection, tool name, title, description, input schema, annotations,
  kind (read, unknown, changes), enabled, hash, reviewed at.
- On `connections`, the side panel: on or off, which tool, what it sends.
- `outside_oauth_clients` (F30) is kept as it is: registrations per authorization server and
  redirect.
- `library_connection_policy` in `server_info`: who may add, the address list, admin presets.

### Code

- `src/mcpClient.ts` (F30) grows: `initialize` reports the server's name, version and
  capabilities; `tools/list` keeps annotations and pages through `nextCursor`; server-initiated
  requests are answered "not supported".
- `src/connections.ts` (new): probe, sign in (generalising F30's Recall OAuth: discovery by
  `WWW-Authenticate` and RFC 9728, registration by RFC 7591 or a client ID metadata document,
  PKCE), keep, review, hold on change, disconnect and revoke.
- `src/outside.ts` becomes the assistant's side: specs from the enabled tools, the send-out rule,
  the always-ask rule for unknown tools, results framed and clipped.
- `GET /api/vaults/:v/notes/:id/connections`: the side panel's lookups for the open note, per
  person, cached ten minutes.
- `web/components/Connections*.tsx`: the list, the guided dialog, Review. Shared UI only.
- Tests: the fakes in `test/fakeMcp.ts` grow a third service, one with a write tool (never
  offered), an unannotated tool (asks every time), lying annotations, a tool that changes between
  lists, an OAuth server without PKCE (refused), no sign-in (the warning), and one that tries
  `sampling` (declined); the side panel's lookup sends only the title.

### Steps

1. **The core, with Longview and Recall as presets (M), built 2026-11-01:** the tables and their move from F30,
   `src/connections.ts`, read-only sorting of tools, the assistant using enabled tools, the hash
   and hold on change, the list and Review in Settings. Nothing new for people yet except Review.
2. **Any service with a token, or none (M), built 2026-11-01:** Add a connection… with the probe, the token step
   (and the no-sign-in warning), choosing tools, the test, and the bar's plain-word failures;
   services on the same Mac allowed on the kit.
3. **Any service with OAuth (M):** discovery from `WWW-Authenticate`, registration (dynamic or a
   client ID metadata document), read scopes only.
4. **From your connections, in the side panel (S–M), built 2026-11-01:** the per-connection switch and what it
   sends, the lookup route, the section. Takes in F30 step 3 ("In Longview").
5. **Admin policy and presets (S):** who may add, the address list, admin presets.
6. **Later, if wanted:** the service's resources (read a document by link) and prompts.

**Done when** a person connects a service they found (not a preset) by its address alone,
guided to a working connection or a clear reason it can't be one; the assistant uses its read
tools under the send-out rule, never sees a tool that changes things, and asks every time before
an unknown one; a service with no sign-in connects only past its warning; the side panel shows
what a connection has on the open note, sending only its title and type, once turned on; a
change to a service's tools holds it until reviewed; services on the same Mac connect on the kit
and not in the cloud; Longview and Recall work as before, as presets; and none of it is offered
over Commonplace's MCP server.

---

## Decisions (David, 2026-11-01)

1. **Read-only.** Connections never change anything in a service: tools that change things are
   never offered (Part 1 §4). Unannotated tools can be turned on past a warning, and always ask.
2. **Everyone** in the library may add connections, by default; an admin can narrow it.
3. **No sign-in** is allowed, past a warning.
4. **The assistant and the side panel**: the side panel is step 4, not "later".
5. **Services on the same Mac** are allowed by default on the laptop kit (never in the cloud).
