# F26 — `#Type` inline

Done in v0.0.58 (2026-10-26). The design as agreed in the backlog, then what was built.

**Size** S · **Evidence** "Turn into a typed note…" (v0.0.29) already makes a typed note from a
selection; the `#` menu offers tags (`web/lib/`), and F20 added 15 starter types.

In the editor, `#` followed by a type's name (`#Person`) offers "New Person…" next to the
tags. Choosing it and typing a title (`#Person Sam Okafor`, then Enter) makes the note from the
type's template in the type's folder, and leaves a `[[Sam Okafor]]` link where the text was.
A tag with the same name as a type still works as a tag.

**Done when** it works in Live Preview on the laptop and the iPhone, Undo puts the text back,
and a browser test makes a note this way.

## As built

- `web/components/Editor.tsx`: the `#` completion lists each type as **New Person…** after the
  tags. Choosing it leaves `#Person ` and records where its `#` is (`typedHash`, a state field
  mapped through edits, cleared when the cursor leaves the line or the text no longer starts
  `#Person `). While that holds, `typedTitleCompletions` offers **New Person “Sam Okafor”** (or
  **Link to “…”** when a note of that title exists); Enter replaces the run with `[[Sam Okafor]]`
  as its own undo step and makes the note with `createTypedNote`, as Turn into a typed note does.
- Only a choice from the menu starts it, so a tag typed by hand that shares a type's name
  (`#book`) never offers to make a note while you go on writing.
- The note goes at the top of the collection, as Turn into a typed note does; types have no
  folder of their own yet.
