# F25 — OAuth sign-in for the MCP server

Done in v0.0.57 (2026-10-26). The design as agreed in the backlog, then what was built.

**Size** M · **Evidence** `docs/MCP.md`: claude.ai's custom connectors (and so the Claude iPhone
and desktop apps) need OAuth; today only Claude Code and `mcp-remote` work, with a bearer token
from Settings → Connections (`src/tokens.ts`, `src/mcp.ts`).

The MCP server offers OAuth 2.1 with PKCE, as the MCP authorization spec asks: metadata at the
well-known addresses, dynamic client registration, and a consent page in the app ("Claude wants
to read and write your notes as you", with read-only as a choice). Signing in issues the same
kind of hashed, scoped, revocable token as today, listed in Settings → Connections with the
client's name and last use. Bearer tokens keep working.

**Done when** claude.ai adds Commonplace as a custom connector, searches and reads notes and
(when allowed) writes one, the token shows in Connections and revoking it cuts Claude off at
once, and an e2e test drives the whole flow with a fake client.

## As built

- `src/oauth.ts`: protected-resource metadata (RFC 9728) at `/.well-known/oauth-protected-resource`
  and `/…/mcp`; authorization-server metadata (RFC 8414); dynamic client registration (RFC 7591)
  for public clients (`none`) and ones with a secret (`client_secret_post`, `client_secret_basic`);
  the token endpoint (authorization code with PKCE S256, refresh with rotation); revocation
  (RFC 7009). `resource` (RFC 8707) must name this server if given.
- `/mcp` answers 401 with `WWW-Authenticate: Bearer … resource_metadata="…"`, and
  `error="invalid_token"` when a token was sent but has expired or been revoked.
- The consent page is the app's own (`web/components/OAuthConsent.tsx` at `/oauth/authorize`),
  after the usual sign-in; it asks `/api/oauth/request` and answers through `/api/oauth/approve`
  (cookie, same origin), which returns the address to go back to.
- A sign-in is an `api_tokens` row with `client_id`, `expires_at` and `refresh_hash`: listed in
  Connections as "signed in from <host>", with Disconnect.
- Not done: Client ID Metadata Documents (the 2025-11-25 alternative to registration); clients
  fall back to registration, which claude.ai and Claude Code both support.
